# Frontend

Next.js 15 (App Router), React 19, TypeScript strict. Один проект обслуживает три разных продукта: публичный сайт, кабинет студента и админку — с разными стратегиями рендеринга.

## 2. Стратегия рендеринга по маршрутам

| Маршрут | Режим | Обоснование |
|---|---|---|
| Лендинг, каталог, карточка курса | **SSG + ISR** (revalidate 300, on-demand по вебхуку публикации) | SEO на двух языках, быстрый TTFB из CDN |
| Страница верификации сертификата | SSG on-demand | публичная, индексируемая |
| Кабинет, список курсов | **SSR** | персонализировано, `no-store` |
| Страница урока | **SSR-оболочка + client-контент** | доступ проверяется на сервере, контент грузится клиентом с `ETag` |
| Квиз | **CSR** | состояние живёт в браузере, вопросы приходят по API |
| Админка | **CSR** | SEO не нужен, меньше серверной нагрузки |

Важное: **проверка доступа к уроку делается на сервере до рендера**. Если `AccessPolicy` вернул `paywall` — SSR отдаёт экран покупки, а не мигание контентом. Клиентская проверка — только UX-слой.

## 3. BFF

Route Handlers в `app/api/` — тонкий слой:

1. Читают HttpOnly-cookie, подставляют `Authorization: Bearer`.
2. На `401` дёргают `/auth/refresh`, ставят новые cookie, **повторяют исходный запрос один раз**.
3. Прокидывают `Accept-Language`, `X-Request-Id`, `X-Client`.
4. Ничего не решают по бизнесу. Вся авторизация — на FastAPI.

Cookie:
```
mada_at  HttpOnly Secure SameSite=Lax Path=/  Max-Age=900
mada_rt  HttpOnly Secure SameSite=Lax Path=/api/auth  Max-Age=2592000
```
`Path` у refresh-токена сужен намеренно: он не должен уходить с каждым запросом.

CSRF: для мутаций — double-submit токен в заголовке `X-CSRF-Token` + значение в не-HttpOnly cookie. `SameSite=Lax` покрывает большинство случаев, но не все.

## 4. Работа с данными

- **TanStack Query** — весь серверный стейт. `staleTime` по типу данных: каталог 5 мин, структура курса 10 мин, прогресс 0.
- **Zustand** — только эфемерное состояние виджетов: позиция плеера, черновик ответов квиза, состояние редактора.
- Никакого глобального Redux-подобного стора. Серверные данные не дублируются в клиентском сторе — это главный источник рассинхрона.
- Оптимистичные апдейты — на прогрессе урока, закладках, реакциях. Не на деньгах и не на сдаче квиза.
- Ключи запросов централизованы:
```ts
export const qk = {
  course: (id: string, locale: Locale) => ["course", id, locale] as const,
  lesson: (id: string, locale: Locale) => ["lesson", id, locale] as const,
  progress: (courseId: string) => ["progress", courseId] as const,
};
```
**Локаль обязана быть частью ключа кэша.** Иначе переключение языка отдаёт закэшированный контент чужого языка — самый частый баг двуязычных SPA.

## 5. Дизайн-система

### Токены

```css
:root {
  --color-bg / --color-surface / --color-fg / --color-muted
  --color-primary / --color-primary-fg / --color-accent
  --color-success / --color-warning / --color-danger
  --radius-sm|md|lg
  --space-1..12                    /* шаг 4px */
  --font-sans-latin / --font-sans-arabic
  --shadow-sm|md|lg
}
```
Тёмная тема — `prefers-color-scheme` + ручной переключатель через `data-theme` на `<html>`, приоритет у ручного.

### Типографика по направлению
```css
:root[dir="ltr"] { --leading-body: 1.5;  --text-base: 1rem;     --tracking: -0.01em; }
:root[dir="rtl"] { --leading-body: 1.8;  --text-base: 1.0625rem; --tracking: 0; }
```
`letter-spacing` для арабского — строго `0`. Подробности — [i18n-rtl.md](i18n-rtl.md) §4.

### Правила компонентов
- Только логические CSS-свойства (`ps-*`, `me-*`, `text-start`, `border-e`). ESLint запрещает физические.
- Каждый компонент в Storybook снимается в `ltr` и `rtl`.
- shadcn-компоненты после установки проверяются на физические направления — генератор их местами оставляет.
- Минимальная область нажатия 44×44 px — трафик преимущественно мобильный.
- Фокус видимый всегда (`:focus-visible`), контраст ≥ 4.5:1 — на арабском шрифте проверять отдельно, тонкие начертания проседают.

## 6. Рендерер контент-блоков

```ts
// components/blocks/registry.ts
export const blockRegistry = {
  heading: HeadingBlock,
  paragraph: ParagraphBlock,
  list: ListBlock,
  quote: QuoteBlock,
  callout: CalloutBlock,
  table: TableBlock,
  math: MathBlock,
  divider: DividerBlock,
  image: ImageBlock,
  gallery: GalleryBlock,
  video: VideoBlock,
  audio: AudioBlock,
  file: FileBlock,
  embed: EmbedBlock,
  code: CodeBlock,
  quiz: QuizBlock,
  flashcards: FlashcardsBlock,
  checklist: ChecklistBlock,
  accordion: AccordionBlock,
  tabs: TabsBlock,
  hotspot: HotspotBlock,
  mermaid: MermaidBlock,
  cta: CtaBlock,
} satisfies Record<BlockType, ComponentType<BlockProps>>;
```

- Неизвестный тип блока рендерится как заглушка, а не роняет страницу: старый клиент должен переживать новый контент.
- Тяжёлые блоки (`math`, `mermaid`, `code`, `hotspot`) — через `next/dynamic`, чтобы KaTeX и highlighter не лежали в основном бандле.
- `IntersectionObserver` на блоках пишет `blocksSeen` в прогресс — из этого потом строится «докуда дочитали».
- Блоки `code`, `math`, `embed` принудительно `dir="ltr"` внутри RTL-страницы.

Добавление нового типа блока = компонент + zod-схема + нода TipTap + пункт тулбара. Миграций БД нет.

## 7. Видеоплеер

Vidstack поверх hls.js.

Требования:
- Сохранение позиции: heartbeat каждые 20 с + на `pause`, `visibilitychange`, `pagehide` (через `sendBeacon`).
- Возобновление с последней позиции при открытии, с предложением «начать сначала».
- Скорость 0.75×–2×, запоминается в профиле.
- Субтитры `ar` / `en`, выбор дорожки, размер и фон подписи.
- Главы (chapters) из блока `video`.
- Горячие клавиши: пробел, ←/→ ±10 с (**в RTL стрелки не меняют смысл — ← всегда назад по времени**), ↑/↓ громкость, `F`, `M`, `C`.
- PiP, полноэкранный, `playsinline` на iOS.
- Watermark: полупрозрачный слой с именем и id студента, перемещается каждые 30 с.
- **Панель управления — `dir="ltr"`** даже в арабском интерфейсе. Меню качества, субтитров и глав — RTL по локали.
- Ошибка загрузки сегмента → авто-ретрай с понижением качества, а не «чёрный экран».

Ссылку на воспроизведение выдаёт `/media/assets/{id}/playback` с TTL 4 часа; плеер сам перезапрашивает её при истечении во время длинного просмотра.

## 8. Раннер квиза

- Ответы хранятся в Zustand + автосохранение на сервер с debounce 800 мс и повтором при офлайне.
- Черновик дублируется в `localStorage` по `attemptId` — на случай перезагрузки вкладки.
- Таймер — только визуализация `deadline_at` с сервера; расхождение часов клиента компенсируется дельтой, посчитанной при старте.
- За 60 с до дедлайна — предупреждение, по истечении — автосабмит.
- Навигация по вопросам, панель «отвеченные / пропущенные / отмеченные».
- Один вопрос на экран на мобильном, список — на десктопе.
- Отправка блокирует UI, повторный `submit` невозможен (кнопка + идемпотентность на сервере).
- a11y: каждый вопрос — `<fieldset>` с `<legend>`, варианты — настоящие radio/checkbox, полная клавиатурная навигация. Кастомные `div`-«радиокнопки» ломают скринридеры и на арабском особенно.

## 9. Редактор курса (админка)

TipTap с кастомными нодами под каждый тип блока.

- Панель локалей: переключение `ar`/`en` без потери несохранённых изменений, режим «бок о бок» для перевода.
- Автосохранение draft каждые 5 с, явная кнопка «Опубликовать».
- Загрузка медиа — drag&drop, прямой presigned-аплоад с прогрессом и возможностью отмены.
- Предпросмотр «как видит студент» в обоих направлениях.
- Блокировка одновременного редактирования: мягкий lock на 5 минут с показом «редактирует Х».
- Валидация перед публикацией: все блоки валидны, у видео статус `ready`, обязательные поля локали заполнены.

## 10. Производительность

Целевые метрики на 4G, устройство среднего класса:
- LCP < 2.5 с на карточке курса
- INP < 200 мс на странице урока
- Основной бандл < 200 КБ gzip

Как достигается:
- Шрифт **только текущей локали**, сабсет по арабским unicode-диапазонам, `preload` одного начертания.
- `next/image` для всех изображений, AVIF/WebP, явные размеры.
- Тяжёлые библиотеки (TipTap, KaTeX, hls.js, Recharts) — только через `next/dynamic`.
- Админка полностью в отдельных чанках — студент её код не грузит.
- ISR для каталога, `stale-while-revalidate` на CDN.
- Cloudflare перед приложением: PoP в Маскате/Дубае/Эр-Рияде решают проблему origin в Европе для статики.

## 12. Тестирование

| Уровень | Инструмент | Что покрываем |
|---|---|---|
| Unit | Vitest | форматтеры (деньги, даты, хиджра), нормализация арабского, утилиты |
| Component | Testing Library | блоки, раннер квиза, формы |
| Visual | Storybook + снапшоты | каждый компонент в `ltr` и `rtl` |
| E2E | Playwright | сквозные сценарии, **прогон дважды: ar/rtl и en/ltr** |

Обязательные e2e с первой недели:
1. Регистрация по OTP → покупка → доступ к курсу → прохождение урока → квиз → сертификат.
2. Переключение локали в середине курса: прогресс сохраняется, контент меняется, кэш не отдаёт чужой язык.
3. Возврат из Thawani: успех, отмена, закрытая вкладка (заказ дозакрывается воркером сверки).
