# Движок квизов

Отдельный модуль с одним жёстким инвариантом:

> **Правильные ответы никогда не покидают сервер во время попытки. Грейдинг только на сервере.**

Всё остальное — детали. Нарушение этого правила означает, что любой студент с открытой вкладкой DevTools видит ответы, и вся статистика курса — мусор.

---

## 1. Типы вопросов

### v1

| Тип | Описание | Формат `answer` |
|---|---|---|
| `single` | один вариант из нескольких | `{ "optionId": "uuid" }` |
| `multiple` | несколько вариантов | `{ "optionIds": ["uuid", …] }` |
| `boolean` | верно / неверно | `{ "value": true }` |
| `short_text` | короткий ответ текстом | `{ "text": "…" }` |
| `number` | число с допуском | `{ "value": 3.14 }` |

### Фаза 3

| Тип | Описание | Формат `answer` |
|---|---|---|
| `matching` | соответствие левое↔правое | `{ "pairs": [{ "leftId": "…", "rightId": "…" }] }` |
| `ordering` | расставить по порядку | `{ "order": ["id1", "id2", …] }` |
| `fill_blank` | пропуски в тексте | `{ "blanks": { "b1": "…", "b2": "…" } }` |
| `essay` | развёрнутый ответ, ручная проверка | `{ "text": "…", "fileIds": [] }` |
| `hotspot` | клик по области изображения | `{ "x": 0.42, "y": 0.71 }` (доли) |
| `code` | код с автотестами | `{ "lang": "python", "source": "…" }` |

`hotspot` хранит координаты в **долях**, а не в пикселях — иначе ответ ломается при другом размере изображения.

## 2. Локализация вопросов

`prompt` и `content` вариантов — JSONB с локалями, внутри которых лежат блоки (тот же формат, что и контент урока):

```json
{
  "prompt": {
    "ar": [{ "type": "paragraph", "data": { "text": "ما هو ناتج ٢ + ٢؟" } }],
    "en": [{ "type": "paragraph", "data": { "text": "What is 2 + 2?" } }]
  }
}
```

Правила:
- Попытка фиксирует локаль (`quiz_attempts.locale`) — студент не может переключить язык в середине и увидеть другую формулировку.
- **Квизы не переводятся машинно.** Формулировка вопроса — часть измерения; кривой перевод превращает статистику сложности в шум. Только человеческий перевод, статус `human_review` минимум.
- Статистика по вопросу (`p-value`, дискриминативность) считается **раздельно по локалям**. Расхождение показателей между `ar` и `en` — сигнал, что один из переводов плохой. Это самая полезная метрика качества перевода, которую можно получить бесплатно.

### RTL в вопросах

- Числа, формулы, код внутри арабского вопроса — в `dir="ltr"`.
- Варианты ответа с латинскими значениями («A», «B», «2.5 kg») выравниваются по началу строки, но само содержимое — LTR.
- В `ordering` направление перетаскивания зеркалится, «первый» элемент — справа.
- В `matching` левая колонка визуально становится правой; логика хранения (`leftId`/`rightId`) не меняется, меняется только рендер.

## 3. Жизненный цикл попытки

```
                 POST /quizzes/{id}/attempts
                          │
        ┌─────────────────▼─────────────────┐
        │ проверки на сервере:               │
        │  • AccessPolicy → доступ к уроку   │
        │  • attempts_used < max_attempts    │
        │  • нет активной попытки            │
        │    (частичный уникальный индекс)   │
        └─────────────────┬─────────────────┘
                          │
              выборка вопросов: questions_per_attempt из банка,
              shuffle_seed фиксируется в попытке,
              question_ids[] сохраняются,
              deadline_at = now() + time_limit  ← считает СЕРВЕР
                          │
                     status = in_progress
                          │
       PUT /attempts/{id}/answers/{questionId}   ← автосохранение, upsert, идемпотентно
                          │
        ┌─────────────────┴─────────────────┐
        │                                   │
   POST /submit                       дедлайн истёк
        │                                   │
        └────────────► грейдинг ◄───────────┘
                          │
              score, passed, обновление прогресса,
              выдача бейджей, событие quiz.submitted
                          │
                     status = graded
                          │
              GET /attempts/{id}/result   ← по review_policy
```

Ключевые решения:

- **`shuffle_seed` фиксируется в попытке.** Порядок вопросов и вариантов воспроизводим при перезагрузке страницы — иначе студент теряет ориентацию, а сохранённые ответы «съезжают».
- **`question_ids[]` фиксируются при старте.** Иначе при выборке N из банка перезагрузка выдаёт другие вопросы.
- **Дедлайн серверный.** Клиентский таймер — индикатор. Разница часов клиента компенсируется дельтой, посчитанной при старте попытки.
- **Истёкшая попытка не теряет ответы.** Всё автосохранённое до дедлайна оценивается; `submit` после дедлайна возвращает `410 quiz.attempt_expired`, но результат уже посчитан фоновой задачей.
- **Параллельные попытки блокируются индексом БД**, а не проверкой в коде: две вкладки открываются за миллисекунды.

```sql
create unique index on quiz_attempts (user_id, quiz_id) where status = 'in_progress';
```

## 4. Грейдинг

### Схемы Pydantic — защита на уровне типов

```python
class OptionForAttempt(BaseModel):       # то, что уходит студенту
    id: UUID
    content: LocalizedBlocks
    # is_correct физически отсутствует в модели

class OptionForReview(BaseModel):        # то, что уходит после submit по review_policy
    id: UUID
    content: LocalizedBlocks
    is_correct: bool
    feedback: LocalizedText | None
```

Разные модели, а не флаг «не забыть исключить поле». Забыть флаг легко, забыть отсутствующее поле — невозможно.

### Правила по типам

**`single`** — совпадение с единственным `is_correct`. Полный балл или ноль.

**`multiple`** — три политики, задаются в `quiz.config`:
- `all_or_nothing` (по умолчанию) — балл только за точное совпадение множеств;
- `partial` — `max(0, (правильных выбрано − неправильных выбрано) / всего правильных)`;
- `per_option` — балл за каждый верный выбор и верный пропуск.
Отрицательный итог обрезается нулём. Политика показывается студенту до старта — иначе это ощущается как несправедливость.

**`short_text`** — нормализация перед сравнением:
1. trim, схлопывание пробелов;
2. регистр — по `config.case_sensitive` (по умолчанию нечувствительно);
3. **для арабского — та же нормализация, что в поиске** (см. [i18n-rtl.md](i18n-rtl.md) §6): огласовки, алиф, та марбута, йа, татвиль. Без этого правильный ответ, набранный с хамзой, засчитывается как ошибка — это выглядит как сломанный тест;
4. список допустимых вариантов (`config.accepted[]`), опционально regex;
5. опционально — расстояние Левенштейна ≤ N для опечаток.

**`number`** — сравнение с допуском: абсолютным (`± 0.01`) или относительным (`± 1%`). Единицы измерения — отдельным полем, не в тексте ответа.

**`matching` / `ordering`** — по умолчанию частичный балл за верную пару/позицию, `all_or_nothing` опционально. Для `ordering` осмысленнее считать по числу верных соседних пар, чем по абсолютным позициям: одна ошибка в начале не должна обнулять весь ответ.

**`essay`** — `points_awarded = null`, статус попытки `submitted` (не `graded`), попадает в очередь куратора. Итоговый балл квиза считается после ручной проверки.

**`code`** — запуск в изолированном контейнере с лимитами CPU/памяти/времени и без сети. Фаза 4, не раньше: безопасная песочница — отдельный проект.

## 5. Античит

Реалистичный набор для образовательной платформы (не для сертификационного экзамена):

| Мера | Что даёт |
|---|---|
| Серверный таймер и дедлайн | нельзя «остановить время» |
| Перемешивание вопросов и вариантов с уникальным seed | ответы не передаются по номерам «1-B, 2-C» |
| Выборка N из большого банка | у соседей разные вопросы |
| Одна активная попытка | нельзя открыть несколько и сравнить |
| Правильные ответы не уходят на клиент | DevTools бесполезны |
| Лимит попыток + окно между попытками | нельзя перебором нащупать ответы |
| Логирование `blur`/`focus` вкладки | сигнал, не блокировка |
| Скорость ответа аномально высокая | сигнал для отчёта преподавателю |

Чего **не** делать: блокировать копирование, запрещать переключение вкладок, требовать вебкамеру, детектить DevTools. Это раздражает честных студентов, обходится за минуту и создаёт ложное ощущение защищённости. Если нужен прокторинг — это отдельный внешний сервис и отдельное решение.

## 6. Аналитика по вопросам

Ночной пересчёт `questions.stats` **раздельно по локалям**:

| Метрика | Формула | Как читать |
|---|---|---|
| `p_value` | доля верных ответов | < 0.3 — слишком сложно или плохо сформулировано; > 0.95 — не различает |
| `discrimination` | корреляция «верно на этом вопросе» × «итоговый балл» | < 0.15 — вопрос не работает; отрицательная — почти всегда ошибка в ключе |
| `avg_time_seconds` | среднее время | аномально долго — путаная формулировка |
| `distractor_usage` | доля выбора каждого неверного варианта | вариант, который не выбирает никто, бесполезен |
| `locale_delta` | \|p_value(ar) − p_value(en)\| | > 0.2 — почти наверняка проблема перевода |

В админке — отчёт «вопросы, требующие внимания», отсортированный по этим сигналам. Это превращает квизы из «поставили и забыли» в инструмент, который улучшает сам курс.

## 7. Итоговый экзамен и сертификат

- `is_final_exam = true`, обычно: одна-две попытки, ограничение по времени, `review_policy = after_pass`, повышенный проходной балл.
- Сертификат выдаётся при выполнении **всех** условий курса: обязательные уроки пройдены, домашние задания приняты, экзамен сдан. Проверка — в одном сервисе (`certificate.eligibility`), а не разбросана по обработчикам.
- Балл в сертификате — из финального экзамена, не средний по курсу (иначе непонятно, что он означает).

## 8. Доступность

- Каждый вопрос — `<fieldset>` + `<legend>`, варианты — нативные `<input type="radio|checkbox">` со стилизацией. Кастомные `div`-«кнопки» ломают скринридеры, а на арабском — особенно заметно.
- Таймер — `aria-live="polite"` с объявлением на отметках 5 и 1 минута, а не каждую секунду.
- Полная клавиатурная навигация: Tab по вариантам, Space для выбора, стрелки внутри группы.
- `matching`/`ordering` — обязательная клавиатурная альтернатива drag&drop (кнопки «вверх/вниз», выпадающие списки). Без неё эти типы вопросов недоступны части пользователей.
- Ошибки валидации — связаны с полем через `aria-describedby`, не только цветом.

## 9. Чек-лист готовности модуля

- [ ] `is_correct` отсутствует в схеме ответа во время попытки (проверено тестом на сериализацию)
- [ ] Параллельные попытки блокируются индексом БД
- [ ] Перезагрузка страницы сохраняет порядок вопросов и ответы
- [ ] Истёкшая попытка оценивается по автосохранённым ответам
- [ ] Арабская нормализация работает в `short_text` (тест с хамзой и огласовками)
- [ ] Политика частичного балла отображается студенту до старта
- [ ] Статистика по вопросам считается по локалям, отчёт «проблемные вопросы» работает
- [ ] Клавиатурная альтернатива drag&drop реализована
- [ ] e2e: старт → автосохранение → обрыв сети → восстановление → submit → результат
