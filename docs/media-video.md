# Медиа: загрузка, обработка, воспроизведение

Видео — самая дорогая часть платформы по инфраструктуре и самая заметная по качеству опыта. Здесь три отдельных решения: как загружать, как обрабатывать, как отдавать.

---

## 1. Принципы

1. **Приложение не проксирует медиа.** Ни на загрузке, ни на отдаче. Браузер работает с бакетом напрямую по подписанным ссылкам. Иначе один VPS упирается в сеть на десятке одновременных зрителей.
2. **Абстракция провайдера с первого дня.** `MediaProvider` с реализациями `s3` и `cloudflare_stream`. Поле `provider` есть в `media_assets` изначально — переезд станет сменой значения, а не миграцией схемы.
3. **CDN — сразу, не «когда вырастем».** Origin в Европе + Cloudflare с PoP в Маскате, Дубае, Дохе, Эр-Рияде, Джидде, Кувейте, Манаме. Без CDN опыт на мобильном интернете региона будет плохим с первого дня.

## 2. Загрузка

```
Админ выбирает файл
   │
   ├─▶ POST /media/uploads { filename, sizeBytes, mimeType, kind, locale }
   │     API: валидация (расширение, размер, квота) → создаёт media_assets(status=uploading)
   │     → presigned PUT           (файл < 100 МБ)
   │     → multipart: uploadId + presigned URL на каждую часть (файл ≥ 100 МБ)
   │
   ├─▶ Браузер льёт напрямую в R2/MinIO, показывает прогресс, умеет отменить и продолжить
   │
   └─▶ POST /media/uploads/{id}/complete { parts[] }
         API: CompleteMultipartUpload → status=processing → задача в очередь
```

Проверки на стороне API:
- белый список MIME и расширений, **проверка магических байтов** после загрузки, а не доверие заголовку;
- лимит размера по типу (видео 5 ГБ, изображение 20 МБ, документ 100 МБ);
- квота организации;
- изображения переупаковываются воркером (снимается EXIF, генерируются WebP/AVIF-варианты) — заодно убивает полезную нагрузку в «картинке».

`upload_sessions` хранит `uploadId` и части, чтобы прерванная загрузка продолжалась, а брошенные multipart-загрузки чистились по расписанию (иначе они молча копят оплачиваемое место).

## 3. Обработка

### v1: без транскода

Отдаём загруженный MP4 как есть. Воркер только:
- `ffprobe` → длительность, разрешение, кодек, битрейт;
- постер: кадр на 10% длительности + возможность заменить вручную;
- проверка «пригодности»: H.264 + AAC, `moov`-атом в начале (`faststart`) — если нет, делаем `ffmpeg -c copy -movflags +faststart` (секунды, не часы);
- `status = ready`.

Плюсы: мгновенно, дёшево, работает. Минусы: нет адаптивного качества — на слабой мобильной сети зритель ждёт буферизацию вместо автоматического понижения до 480p. Для запуска приемлемо, для роста — нет.

### Фаза 3: HLS-лестница

```
1080p  H.264 high   ~4500 kbps
 720p  H.264 main   ~2500 kbps
 480p  H.264 main   ~1200 kbps
 360p  H.264 base    ~700 kbps   ← критично для мобильных сетей региона
```
Сегменты 4 с, `master.m3u8`, аудио отдельной дорожкой (нужно для видео с двумя озвучками).

Реальная цена: час исходника в 4 качества на 4 vCPU — **30–60 минут при 100% загрузке CPU**. Поэтому:
- воркер транскода с жёстким лимитом `cpus: 2`, чтобы API продолжал отвечать;
- очередь с приоритетами, тяжёлые задачи ночью;
- при объёме больше нескольких часов видео в неделю — вынести на отдельную машину или перейти на managed.

### Развилка: свой ffmpeg vs Cloudflare Stream

| | Свой ffmpeg + R2 | Cloudflare Stream |
|---|---|---|
| Стоимость | только хранение и CPU VPS | помесячно за минуты хранения + за просмотренные минуты |
| Транскод | твоя забота, часы CPU | включён |
| Адаптивный битрейт | сам собираешь лестницу | из коробки |
| Подписанное воспроизведение | presigned URL | signed tokens, встроено |
| Ограничение по домену/сессии | сам | встроено |
| Аналитика просмотра | сам | встроено |
| Контроль | полный | ограничен |
| Переезд | — | абстракция `MediaProvider` делает его сменой env |

Рекомендация: **v1 — прогрессивный MP4 на R2. Когда каталог перевалит за десятки часов видео — Cloudflare Stream**, а не собственная транскодинг-ферма. Разработка и эксплуатация своей фермы стоит дороже, чем счёт за managed, пока платформа не очень крупная.

## 4. Субтитры и транскрипты

- Ручная загрузка `.vtt` / `.srt` на локаль (`subtitles.locale`).
- Автогенерация — Whisper (`large-v3`) в воркере: арабский распознаётся приемлемо, но **всегда требует человеческой вычитки** — диалекты Залива отличаются от литературного арабского, и автосубтитры без правки выглядят неряшливо. Статус `is_auto_generated` показывается студенту.
- Транскрипт сохраняется посегментно с таймкодами → поиск по видео («в какой момент говорили про X») и переход по клику.
- Транскрипт индексируется с арабской нормализацией (см. [i18n-rtl.md](i18n-rtl.md) §6).
- Отображение субтитров: RTL для арабских, настройка размера и фона — на мобильном в светлой комнате белый текст без подложки нечитаем.

## 5. Воспроизведение и защита

### Выдача ссылки

```
GET /media/assets/{id}/playback
  → AccessPolicy.check(user, lesson)     ← авторитетная проверка доступа
  → presigned URL, TTL 4 часа
  → лог выдачи: user, asset, ip, ua, время
  → { hlsUrl | mp4Url, posterUrl, subtitles[], watermark, expiresIn }
```

Публичных URL на платное видео не существует. Обложки, промо-ролики и превью-уроки — отдельный публичный префикс бакета, они кэшируются CDN нормально.

### Реалистичная защита

Без DRM (Widevine / FairPlay / PlayReady) видео **скачиваемо** — расширения браузера справляются с HLS так же, как с MP4. Это не решается обфускацией. Что реально работает:

| Мера | Что даёт |
|---|---|
| Подписанные ссылки, TTL 4 ч | ссылка не живёт вечно и не расходится по чатам |
| Watermark с именем/id студента поверх плеера, дрейфующий | делает утечку персонализированной — главный сдерживающий фактор |
| Лимит одновременных сессий на аккаунт (2–3) | ломает схему «один аккаунт на группу» |
| Детект аномалий: N IP/городов за сутки, нечеловеческая скорость просмотра | находит шеринг аккаунтов |
| Логирование выдачи playback-ссылок | позволяет доказать источник утечки |
| Referrer/Origin-проверка на Cloudflare Worker | отсекает встраивание на чужих сайтах |

Настоящий DRM — только через managed-сервис. Собственная реализация Widevine нереалистична.

### Ограничение по сессиям

Redis-ключ `playback:{userId}` с активными сессиями (TTL 5 мин, продлевается heartbeat'ом плеера). Превышение лимита → `409 playback.too_many_sessions` с предложением завершить другие. Аккуратно с порогом: у студента реально бывает телефон + ноутбук.

## 6. Прогресс просмотра

```
Плеер шлёт heartbeat каждые 20 с:
POST /learn/lessons/{id}/progress
{ positionSeconds: 412, watchedDelta: 20, blocksSeen: ["b2"] }
```

- Дополнительно на `pause`, `visibilitychange`, `pagehide` — через `navigator.sendBeacon` (переживает закрытие вкладки).
- Сервер берёт **максимум** позиции, а не последнее значение: опоздавший пакет не должен откатывать прогресс.
- `watchedDelta` суммируется, но с потолком: за интервал 20 с нельзя зачесть больше 25 с — иначе перемотка накручивает просмотр.
- Урок считается пройденным при `watched_seconds ≥ 0.9 × duration` (порог настраивается на курсе).
- Эндпоинт идемпотентен и терпит дубли: сеть в мобильных сетях региона рвётся регулярно.

## 7. Хранение и жизненный цикл

```
media/video/{assetId}/original.mp4
media/video/{assetId}/poster.jpg
media/video/{assetId}/hls/master.m3u8, 720p/*.ts …
media/video/{assetId}/subtitles/{locale}.vtt
media/image/{assetId}/{original,1600,800,400}.{webp,avif}
docs/{courseId}/{assetId}/{filename}
uploads/assignments/{userId}/{submissionId}/{filename}
certificates/{certId}-{locale}.pdf
avatars/{userId}.webp
```

- Оригиналы видео после успешного транскода можно перевести в холодное хранение либо удалить — но только после ручного подтверждения, что HLS корректен. Автоудаление оригиналов — способ потерять контент.
- Брошенные `uploading`-ассеты старше 24 ч чистятся по расписанию вместе с их multipart-загрузками.
- Файлы удалённых домашних заданий удаляются по политике хранения (см. [security-compliance.md](security-compliance.md)).

## 8. Особенности региона

- **Мобильный трафик доминирует.** 360p в лестнице обязателен, дефолтное качество — `auto` с консервативным стартом.
- **Учитывать стоимость трафика у пользователя**: настройка «экономия данных» (ограничить качество на мобильной сети), предупреждение перед автозагрузкой на сотовой связи.
- **Пиковые часы** — вечер после ифтара в Рамадан, тяжёлые фоновые задачи на это время не планировать.
- Origin в Европе даёт ~100–140 мс RTT до Маската; для API это терпимо, для медиа — только через CDN. Если латентность API станет проблемой, рассматривать хостинг в ОАЭ или локальный (см. [deploy-coolify.md](deploy-coolify.md) §1).

## 9. Чек-лист готовности медиа-модуля

- [ ] Загрузка идёт мимо API, multipart работает, прерванная загрузка возобновляется
- [ ] Магические байты проверяются, EXIF снимается, квоты работают
- [ ] `faststart` гарантирован — видео начинает играть без полной загрузки
- [ ] Постер генерируется и заменяется вручную
- [ ] Playback-ссылка выдаётся только через `AccessPolicy`, факт выдачи логируется
- [ ] Watermark отображается и содержит id студента
- [ ] Лимит одновременных сессий работает и не мешает нормальному пользователю
- [ ] Прогресс переживает разрыв сети, перемотка не накручивает просмотр
- [ ] Субтитры на обеих локалях, автосубтитры помечены
- [ ] Брошенные загрузки чистятся по расписанию
- [ ] Транскод не роняет отзывчивость API (лимит CPU проверен нагрузочно)
