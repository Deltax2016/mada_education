# Архитектура

## 0. Контекст, который определяет всё остальное

Три вводных меняют архитектуру сильнее, чем выбор фреймворков:

1. **Арабский как основной язык.** Это не «добавить перевод». Это RTL во всём интерфейсе, двуязычный контент на уровне схемы БД, арабская типографика, нормализация арабского текста для поиска, хиджра-календарь, рабочая неделя вс–чт с выходными пт–сб. Ретрофитить RTL в готовый LTR-продукт — это переписывание фронта. Закладывается с первого коммита.

2. **Рынок Залива.** Локальные платёжные схемы (OmanNet, mada, KNET, Benefit) — не «ещё один провайдер», а обязательное условие: у значительной части клиентов нет международной карты. Валюта OMR имеет **три знака после запятой** (1 риал = 1000 байса), как KWD и BHD. Любой код, который делит на 100, — сломан.

3. **Мобильный трафик.** Вёрстка и вес страниц считаются от телефона на сотовой сети, не от десктопа.

## 2. Стиль: модульный монолит

Один API-процесс, один воркер, одна БД. Не микросервисы: команда маленькая, домен связный, распределённые транзакции здесь не нужны.

Но границы модулей — жёсткие:

> Модуль обращается к другому модулю **только через его `service.py`**. Прямые джойны в чужие таблицы запрещены. Обмен доменными событиями — через внутреннюю шину (`core/events.py`), а не прямыми вызовами, где это возможно.

Это единственное, что позволит потом безболезненно вынести `media` или `billing` в отдельный сервис.

```
apps/api/src/
├── core/
│   ├── config.py            # pydantic-settings, все env в одном месте
│   ├── db.py                # async engine, session, unit of work
│   ├── security.py          # JWT, одноразовые коды, подписи, CSRF
│   ├── deps.py              # FastAPI-зависимости: current_user, require_role, ...
│   ├── errors.py            # RFC 9457 Problem Details, коды ошибок
│   ├── events.py            # доменные события, in-process bus + persist в outbox
│   ├── storage.py           # StorageService (S3 API)
│   ├── i18n.py              # локали, fallback-цепочка, нормализация арабского
│   ├── money.py             # Money(amount_minor, currency), exponent per currency
│   ├── email.py             # Resend: код входа и транзакционные письма
│   ├── ratelimit.py
│   └── logging.py           # structlog + request_id
├── modules/
│   ├── identity/            # пользователи, коды входа по email, сессии, роли
│   ├── catalog/             # категории, курсы, модули, уроки, версии, блоки
│   ├── enrollment/          # доступы, потоки, drip, инвайты, AccessPolicy
│   ├── learning/            # прогресс, позиция видео, завершение, заметки
│   ├── quiz/                # банк вопросов, попытки, грейдинг
│   ├── assignment/          # домашние задания, сдача, ревью
│   ├── media/               # загрузка, presign, транскод, субтитры
│   ├── billing/             # продукты, заказы, подписки, промокоды, провайдеры
│   ├── certificate/         # шаблоны, генерация PDF, верификация
│   ├── social/              # комментарии, Q&A, отзывы
│   ├── gamification/        # очки, бейджи, стрики
│   ├── notify/              # email, in-app, шаблоны, предпочтения

└── workers/                 # ARQ: задачи и планировщик
```

Каждый модуль внутри:
```
models.py      # SQLAlchemy
schemas.py     # Pydantic (in/out)
service.py     # бизнес-логика — единственная публичная точка входа
repository.py  # запросы к БД
router.py      # HTTP
events.py      # что модуль публикует и на что подписан
tasks.py       # фоновые задачи модуля
```

## 4. Контент-модель: блочный редактор + локали

Урок — это не HTML-простыня, а **упорядоченный список типизированных блоков** в JSONB, **отдельно для каждой локали**.

```json
{
  "version": 1,
  "dir": "rtl",
  "blocks": [
    { "id": "b1", "type": "heading", "data": { "level": 2, "text": "مقدمة" } },
    { "id": "b2", "type": "video",   "data": { "assetId": "…", "chapters": [ … ] } },
    { "id": "b3", "type": "callout", "data": { "variant": "info", "content": { … } } },
    { "id": "b4", "type": "quiz",    "data": { "quizId": "…", "mode": "inline" } },
    { "id": "b5", "type": "code",    "data": { "lang": "python", "code": "…", "dir": "ltr" } }
  ]
}
```

Ключевые свойства:

- **Реестр блоков** на фронте: `Record<BlockType, ComponentType<BlockProps>>`. Новый тип = компонент + zod-схема + пункт в тулбаре редактора. **Ноль миграций БД.**
- Валидация `data` — zod на клиенте и дискриминированный union в Pydantic на сервере. Невалидный блок блокирует публикацию.
- `id` блока стабилен между версиями и локалями → к нему можно привязать комментарии и аналитику «докуда дочитали».
- Блоки с кодом, URL, формулами и числами принудительно `dir="ltr"` внутри RTL-страницы.

### Стартовый набор типов блоков

| Категория | Типы |
|---|---|
| Текст | `heading` · `paragraph` · `list` · `quote` · `callout` · `divider` · `table` · `math` (KaTeX) |
| Медиа | `video` · `audio` · `image` · `gallery` · `file` · `embed` (YouTube/Figma/CodeSandbox) |
| Код | `code` · `code-sandbox` (фаза 3) |
| Интерактив | `quiz` · `flashcards` · `checklist` · `accordion` · `tabs` · `hotspot-image` |
| Служебные | `assignment-link` · `cta` · `mermaid` · `glossary-term` |

### Версии и локали

```
lesson
 ├─ lesson_versions(lesson_id, locale='ar', version=7, status='published', content jsonb)
 ├─ lesson_versions(lesson_id, locale='ar', version=8, status='draft',     content jsonb)
 └─ lesson_versions(lesson_id, locale='en', version=3, status='published', content jsonb)
```

- Автор редактирует draft, студенты видят published — курс можно править «на живом».
- Локали независимы: арабская версия может быть опубликована, английская — в переводе.
- `translation_status` на версии: `missing` | `machine` | `human_review` | `done`. Админка показывает матрицу «курс × локаль × готовность».
- Fallback: если запрошенная локаль отсутствует — отдаём `fallback_locale` и помечаем ответ флагом `isFallback`, фронт показывает плашку «этот урок пока только на английском».

Детали локализации — [i18n-rtl.md](i18n-rtl.md).

## 5. Identity: email и одноразовый код

```
Единственный способ входа:  email + код из шести цифр, письмо через Resend
Паролей нет вообще
```

**Почему без пароля:** нечего забывать, сбрасывать, ротировать и утекать. Нет формы восстановления — а это, как правило, самая дырявая часть аутентификации. Первый ввод кода создаёт аккаунт, отдельной регистрации нет.

**Почему не SMS:** alphanumeric sender ID в КСА и ОАЭ регистрируется у операторов неделями, SMS платные за штуку, а SIM-swap в регионе — реальный вектор. Email снимает всё это разом и не требует ничего, кроме верификации домена в Resend.

Запрос кода отвечает одинаково независимо от того, зарегистрирован адрес или нет. Иначе эндпоинт превращается в перечислитель аккаунтов.

**Практический нюанс Resend:** свежий аккаунт умеет отправлять только на адрес владельца, пока не подтверждён домен отправки. До подтверждения `MAIL_FROM` остаётся на `onboarding@resend.dev`. Верификацию домена начинать на Фазе 0.

### Токены

- **Access JWT — 15 минут.** Клеймы: `sub`, `org`, `roles`, `locale`, `sid`.
- **Refresh — 30 дней, с ротацией.** Хранится хэш + `family_id`. Повторное использование отозванного токена ⇒ отзыв всего семейства (детект кражи).
- Оба — в **HttpOnly + Secure + SameSite=Lax cookie**, ставит BFF Next.js. Браузер к API напрямую не ходит, токены не лежат в localStorage.

### Роли и права

Глобальные роли: `student` · `instructor` · `curator` · `support` · `admin`.

Но реальные права — **скоупленные по курсу**: `course_members(course_id, user_id, role)`. Преподаватель курса A не должен видеть студентов курса B. Проверка — через зависимость `require_course_role(course_id, {"instructor", "curator"})`.

### AccessPolicy — единственная точка правды о доступе

Отдельно от RBAC. Отвечает на один вопрос:

```python
access = policy.check(user, lesson)
# → allowed
# → paywall              нет активного enrollment
# → locked_prerequisite  не пройден урок-предусловие
# → locked_schedule      drip ещё не открыл, unlock_at в будущем
# → expired              access_ends_at прошёл
# → not_published        черновик, виден только автору
```

Сводит воедино: enrollment, срок доступа, drip-расписание, граф пререквизитов, `is_preview`, роль в курсе, статус публикации. Проверяется и на BFF (для UX), и на API (авторитетно). Дублировать эту логику где-то ещё — запрещено; это самый частый источник дыр в доступе к платному контенту.

## 6. Асинхронная обработка

| Задача | Триггер | Особенности |
|---|---|---|
| Транскод видео в HLS, постеры | загрузка медиа | лимит CPU, чтобы не задушить API |
| Автосубтитры (Whisper) ar/en | после транскода | опционально, фаза 3 |
| Отправка email | доменные события | шаблоны на обе локали, тихие часы |
| Генерация PDF-сертификата | завершение курса | WeasyPrint, RTL-шаблон |
| **Сверка платежей (reconciliation)** | cron каждые 5 мин | опрос pending-заказов у Thawani — критично, см. §7 |
| Пересчёт прогресса, ночные агрегаты | события + nightly | |
| Напоминания о дедлайнах, дайджесты | cron | учитывать пт–сб как выходные |
| Импорт/экспорт курсов, CSV-выгрузки | админ-действие | |

Все задачи **идемпотентны**, retry с экспоненциальной задержкой, провал после N попыток → `job_failures` + алерт в Sentry.

### Transactional outbox
Доменные события пишутся в таблицу `outbox` **в той же транзакции**, что и изменение данных, а воркер разбирает её отдельно. Иначе классика: платёж записан, а письмо о доступе не ушло, потому что Redis моргнул.

## 7. Платежи: Thawani + мультипровайдер

Абстракция `PaymentProvider` с реализациями. Роутинг по стране пользователя и способу оплаты.

```python
class PaymentProvider(Protocol):
    async def create_checkout(self, order: Order) -> CheckoutSession: ...
    async def fetch_status(self, session_ref: str) -> PaymentStatus: ...
    async def verify_webhook(self, headers, body) -> WebhookEvent | None: ...
    async def refund(self, order: Order, amount: Money) -> RefundResult: ...
```

**Thawani (Оман, основной):**
- Hosted checkout: создаём session → редирект на страницу Thawani → возврат на наш `success_url`/`cancel_url`.
- Суммы передаются в **байсах** (целое, 1 OMR = 1000 baisa). Прямое следствие: деньги во всей системе — `amount_minor: bigint` + `currency` + `exponent` из справочника. Никаких float, никакого деления на 100.
- `client_reference_id` = наш `order.id` → естественная идемпотентность.
- **Возврат на success_url не является подтверждением оплаты.** Пользователь может закрыть вкладку, потерять сеть, подделать URL. Единственный авторитетный источник — серверный `GET /checkout/session/{id}` у Thawani. Плюс фоновая сверка каждые 5 минут по всем заказам в статусе `pending` старше 3 минут. Это не «на всякий случай», это основной путь.
- Есть UAT-окружение — сквозной тест оплаты попадает в CI.

Полный разбор — [billing-gulf.md](billing-gulf.md).

## 8. Медиа

Три решения, зафиксированные заранее:

1. **Загрузка идёт мимо API.** Клиент получает presigned URL (multipart для файлов >100 МБ) и льёт напрямую в бакет. API только выдаёт подпись и принимает `complete`.
2. **v1 — без транскода.** Отдаём прогрессивный MP4. Транскод часа видео в три качества съедает 4 vCPU на 30+ минут. HLS-лестница включается на Фазе 3 или сразу заменяется на Cloudflare Stream.
3. **Cloudflare перед R2 — с самого начала, не «потом».** У Cloudflare есть PoP в Маскате, Дубае, Дохе, Эр-Рияде, Джидде, Кувейте, Манаме. Origin в Европе + CDN на месте = приемлемая скорость. Origin в Европе без CDN = плохой опыт на мобильном интернете в регионе.

Про защиту контента честно: без DRM (Widevine/FairPlay) видео скачиваемо. Реалистичный уровень — короткие подписанные ссылки, watermark с ID студента поверх плеера, лимит одновременных сессий, детект аномалий. Настоящий DRM — только через managed-сервис.

Детали — [media-video.md](media-video.md).

## 9. События и аналитика

Append-only `learning_events` (партиционирование по месяцам, когда таблица вырастет):

```
user_id · course_id · lesson_id · type · payload jsonb · session_id · locale · occurred_at
```

Типы: `lesson_opened`, `block_viewed`, `video_heartbeat`, `video_completed`, `quiz_started`, `quiz_submitted`, `assignment_submitted`, `course_completed`, `checkout_started`, `purchase_completed`, `locale_switched`.

Из них строятся: воронка курса, точки отвала по урокам, сложность и дискриминативность вопросов, retention, **сравнение прохождения ar-версии и en-версии** (полезнее, чем кажется — показывает, где перевод плохой).

Ночной rollup в `daily_stats`. Никакого ClickHouse в v1.

## 10. Наблюдаемость

- **Sentry** — ошибки и трейсы с обеих сторон, релизы по git sha.
- **structlog → JSON в stdout**, `request_id` сквозной: Traefik → Next BFF → API → воркер.
- `/health/live` (процесс жив) и `/health/ready` (Postgres + Redis доступны) — Coolify использует для zero-downtime.

- Бизнес-алерты в отдельный канал: провал платежа, застрявший транскод, очередь длиннее N, всплеск 5xx.

## 12. Заложить сейчас, строить потом

| Что | Что делаем сейчас | Почему нельзя отложить |

| Мультитенантность (B2B) | `organization_id` в ключевых таблицах | добавить в живую БД с данными почти невозможно |
